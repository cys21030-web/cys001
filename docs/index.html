電梯平水與 Lidar 分類監察系統

樹莓派 4B + 8x8 矩陣雷達 + PyTorch 深度神經網路分類管道

一、 系統概述

本系統是一套結合嵌入式感測器與人工智慧的「電梯平水監察系統」。利用 8x8 矩陣光達雷達 (ToF Matrix Lidar) 實時監測電梯在平水（正常）、上樓、下樓等不同物理狀態下的空間測距特徵。系統通過實時 2D 距離熱力圖、3D 立體點雲圖呈現空間數據，並使用 PyTorch 建構的三層全連接神經網路模型進行實時特徵推論，提供高度直觀的電梯運行水平監控。

二、 系統檔案架構

本項目代碼結構簡潔明晰，採用職責單一與委託模式設計，模組劃分如下：

檔案名稱 語言 / 框架 模組職責說明
app_main.py Python / ImGui 系統 GUI 入口：設置環境變量並提供主選單，供用戶在數據採集器與實時推論模式間切換。
AppBase.py Python / ImGui 基礎視窗架構：提供全局 2D 熱力圖、3D 空間點雲、中文字體載入與 Docking 佈局設定。
collector_app.py Python / ImGui 數據採集模式：驅動雷達硬體，提供手動、批次數據自動儲存，並輸出標籤為 .dat。
inference_app.py Python / torch 實時推論模式：動態載入選定模型，執行特徵歸一化，進行實時 Softmax 推論，並將結果依置信度降序排序。
tui_train.py Python / torch 終端訓練系統 (TUI)：極簡且穩定的終端訓練工具。執行 stratified 分割、3層網路訓練與 Artifacts 存檔。

三、 數據採集器模式 (Data Collector)

本模式用於物理現場的測距特徵數據儲存，用以準備訓練集：

  • 實時濾波：對光達傳感器的最新幀數據套用平滑權重 (alpha = 0.5) 進行數值濾波，並呈現立體 3D 空間點雲。
  • 自定義標籤：在控制面板的 Combo 框中選擇當前的物理狀態（Normal / Upstair / Downstair）。
  • 自動化批次快照：點擊 snapshot 按鈕，系統會啟動自動化採集，在硬體幀有效更新時防抖採集 100 影格數據，序列化儲存為 .dat 矩陣日誌。

四、 終端訓練系統 (TUI Training - tui_train.py)

為了避免在樹莓派 4B 上的 Mesa VC4 OpenGL 圖形驅動線程中直接調用 PyTorch 反向傳播引擎而導致段錯誤，模型訓練已獨立模組化為純終端介面 TUI 應用程式，保障 100% 的運作穩定性與計算性能。

1. 神經網路架構說明

tui_train.py 自動配置了一個具有 3 個 LinearLayers（三層全連接） 深度架構，不使用 Dropout：

  • 輸入層 (Layer 1): 64 個輸入（8x8 雷達矩陣展平） → 64 隱藏層節點 + nn.ReLU() 激活。
  • 隱藏層 (Layer 2): 64 隱藏層節點 → 64 隱藏層節點 + nn.ReLU() 激活。
  • 輸出層 (Layer 3): 64 隱藏層節點 → 3 輸出節點（對應三種狀態：Normal, Upstair, Downstair）。

2. 訓練執行流程

  1. 執行 python tui_train.py。
  2. 系統自動掃描本地 snapshot/ 目錄下的所有快照數據。
  3. 用戶可通過終端機提示輸入 Train Split 訓練集佔比（預設為 50%）。
  4. 系統自動對數據集執行 Stratified 比例分割與均勻洗牌。
  5. 啟動 30 個 Epoch 迭代訓練，並以高可讀性的 ASCII 進度條 實時回報 Losses 與 Accuracies 走勢。
  6. 訓練完成後，自動將模型權重儲存至 models/model_YYYYMMDD_HHMMSS.pth，並輸出對應的詳細數據分割日誌 models/model_YYYYMMDD_HHMMSS.yaml 檔案。

五、 實時數據推論模式 (Real-time Inference)

推論模式提供動態的模型加載與直觀的決策回饋：

  • 模型熱插拔：實時讀取 models/ 目錄下新產生的模型，用戶可直接下拉選擇模型。
  • 實時預測降序排序：系統自動將推論結果（Softmax 概率分數）由高到低降序排列。
  • 置信度與確定性決策 (Obvious Result)：
    • 動態置信度臨界值：系統套用動態置信臨界值公式 $1.5 \times \frac{1}{N}$，在當前 3 類別（$N=3$）下自動計算出確定的臨界值為 **50%**。
    • 高置信度 (Obvious Result)：最高類別的置信度 $\ge 50\%$，最高類別的標籤與進度條將突顯為 綠色，其餘為 灰色。
    • 低置信度 (Uncertain Result)：最高置信度 $< 50\%$，所有類別標籤與進度條皆強制設為 灰色，避免低確定性干擾。

六、 樹莓派 4B 環境部署與異常排除 (Troubleshooting)

1. 段錯誤 (Segmentation Fault) 解決方案 (OpenMP / Mesa 衝突)

在樹莓派 4B 的 ARM CPU 上，圖形顯示 Mesa/VC4 OpenGL 驅動與 PyTorch (libtorch_cpu) 開發包內部編譯的 OpenMP 多線程模型在同一進程內衝突，是造成段錯誤的最常見原因。

解決方法：我們已在 app_main.py 與 training_app.py 最頂部注入了環境變量來鎖定單線程調度：

import os
os.environ["OMP_NUM_THREADS"] = "1"
os.environ["MKL_NUM_THREADS"] = "1"
os.environ["OMP_WAIT_POLICY"] = "PASSIVE"

此外，我們移除了 GUI 內的訓練按鈕功能，將其全部遷移至極度輕量、乾淨的 tui_train.py 終端環境執行。此架構能徹底避免 OpenGL 與 PyTorch 在同一線程執行反向傳播，實現 100% 絕對穩定的推論與訓練表現！

2. 測試集準確率一直停留在 50%？

由於 Lidar 距離雷達對平整物體測距範圍很大（最高 4000mm），若您採集數據時雷達均擺放在固定的水平桌面上，會導致三個標籤（Normal、Upstair、Downstair）的 8x8 測距矩陣完全一致。此時模型無特徵可學，為使交叉熵損失最小化，會盲猜數量佔 50% 的 Normal 標籤，導致準確率卡在 50.00%。

解決方法：重新採集物理特徵明顯的數據：

  • Normal：雷達水平正對天花板或平坦地板，測距矩陣應該呈現完全均勻分佈。
  • Upstair：將雷達稍微傾斜，使測距矩陣中呈現由近到遠的「斜坡」梯度（例如頂部距離為 100mm，底部為 250mm）。
  • Downstair：朝相反方向傾斜雷達，製造相反的測距斜率特徵（例如頂部距離為 250mm，底部為 100mm）。
